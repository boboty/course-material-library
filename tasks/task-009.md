# Task 9：调整 Demo 数据导入保护

## 目标

把 Demo 数据命令的保护方式从“数据库地址必须为本机回环”改为“执行前展示目标数据库并要求用户显式确认”，使命令可用于非本机数据库，同时保留误操作保护。

## 范围与边界

1. 移除 `DATABASE_URL` 必须为回环地址的限制；不再因数据库主机拒绝执行。
2. 执行前在终端展示当前目标数据库（驱动、主机、端口、数据库名、用户），不显示密码。
3. 执行前明确提示该命令将清空现有全部业务数据。
4. 仅在用户显式确认后执行；确认以外的任何输入（含直接回车、EOF）视为取消。
5. 取消时不修改任何数据，不进入清理或灌入事务。
6. `make demo-data` 与 `make demo-clean` 共用同一保护路径，两者都会清空业务数据。
7. 保留既有 `APP_ENV` 必须为 `local` / `development` 的判断，不修改。

## 明确不做

不新增其他环境判断、数据库命名规则、权限或鉴权机制；不增加跳过确认的开关；不修改 Demo 数据内容、清理顺序、事务边界或任何业务代码、schema、migration、API 契约。

## 验收

非回环数据库不再被拒绝；执行前输出目标数据库与清空提示；确认后行为与 Task 7 一致（重复灌入结果固定、重复清理后业务表为空且 schema/migration 保留）；取消后数据零变化；`APP_ENV=production` 仍被拒绝；`make check` 通过。
