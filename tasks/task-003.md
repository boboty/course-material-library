# Task 003 — 场次计划素材

## 目标

完成备课流程中的“选择计划素材”这一垂直切片：

**已有场次 → 搜索素材 → 加入计划 → 持久化使用记录 → 场次详情读回 → 可撤销计划**

本 Task 只建立“计划使用什么”的可信事实，不进入课后登记。

## 产品依据

重点阅读 `docs/product-v1.md`：

- 2. 核心实体 / 使用记录
- 4.3 备课
- 7. 主要页面
- 9. 数据沉淀原则

同时遵守 `AGENTS.md` 与 `PROGRESS.md`。

## 本 Task 范围

### 1. 使用记录数据模型

新增“使用记录”实体，连接场次与素材。

至少包含：

- id
- session_id
- material_id
- 使用状态：计划 / 已用 / 未用
- 效果：未评 / 好 / 差
- 现场反应，可选
- created_at
- updated_at

要求：

- 同一场次、同一素材最多一条使用记录；
- `session_id`、`material_id` 必须引用真实实体；
- 本 Task 新建的使用记录固定为：
  - 状态 = `计划`
  - 效果 = `未评`
  - 现场反应 = null
- 数据库约束必须保护状态与效果合法值；
- Schema 变更通过 Alembic，形成 0002 之后的单一 migration head。

本 Task 可以一次建立使用记录的完整字段，但**不得实现课后状态转换和效果登记功能**。

### 2. 场次计划素材 API

提供最小 API，使场次能够：

- 读取当前使用记录；
- 将已有素材加入当前场次计划；
- 从当前场次计划中移除素材。

建议契约：

- `GET /api/v1/sessions/{session_id}/usages`
- `POST /api/v1/sessions/{session_id}/usages`
- `DELETE /api/v1/sessions/{session_id}/usages/{usage_id}`

POST 只接收本 Task 真正需要的 `material_id`，不得允许客户端提前写入“已用 / 未用 / 好 / 差”。

错误语义至少覆盖：

- 场次不存在；
- 素材不存在；
- 同一素材重复加入同一场次；
- 删除不存在或不属于当前场次的使用记录。

错误继续使用项目现有 error envelope，不暴露数据库细节。

### 3. 备课 UI

把场次详情中的“计划素材”占位内容替换为真实功能。

至少做到：

- 场次详情能看到已计划素材；
- 能进入计划素材选择流程；
- 能使用当前已有的素材标题搜索能力搜索全库；
- 搜索结果展示至少：标题、类型、素材状态；
- 能把素材加入当前场次计划；
- 已加入状态清晰可见，不能因为重复点击产生重复记录；
- 能撤销尚处于“计划”状态的素材；
- 刷新或重新进入场次后，计划素材仍然正确存在。

V1 当前所有快速录入素材都是“草稿”，因此本 Task **不得因为素材状态是草稿而禁止计划使用**。

本 Task 不新增素材搜索语义；正文、标签、类型、课程、人群、行业等完整筛选留到后续 Task。

## 冻结语义

### 撤销计划

备课阶段把某素材从计划中移除，表示：

**这个素材不再属于本场计划。**

因此应删除该使用记录，而不是把状态改成“未用”。

“未用”表示课后确认：这个素材原本计划了，但最终没有讲。该语义属于 Task 4。

### 当前不做

本 Task 不实现：

- 已用 / 未用状态转换；
- 好 / 差效果登记；
- 现场反应填写；
- 课后登记页面；
- 现场临时新增素材并记录使用；
- 素材与课程多对多关系；
- 本课程素材优先排序；
- 素材家族；
- 同客户 / 同集团重复提醒；
- 连续两次效果差提示；
- 素材完整编辑与完整筛选；
- Markdown 批量导入；
- 删除场次、客户、课程或素材；
- 新的认证、权限或复杂基础设施。

不要为了 Task 4+ 提前增加接口、页面或抽象。

## 验收场景

至少覆盖以下行为：

1. 新场次没有计划素材时，使用记录为空；
2. 给场次加入一个素材后，生成一条“计划 + 未评”的使用记录；
3. 刷新 / 重新请求后仍能完整读回；
4. 同一场次可以计划多个不同素材；
5. 同一素材不能在同一场次产生两条使用记录；
6. 同一个素材可以被不同场次分别计划；
7. 撤销计划后该使用记录消失，不变成“未用”；
8. 未知场次、未知素材、错误归属的删除都有明确失败响应；
9. 草稿素材允许被计划；
10. Task 1 / Task 2 全部回归通过；
11. 数据模型与 API 中没有提前出现 Task 4 的状态变更能力。

## E2E

至少新增一条真实完整流程：

1. 创建虚构素材；
2. 创建虚构客户、课程、人群类型和场次；
3. 在 UI 中搜索并加入两个计划素材；
4. 重新进入场次详情，确认两个素材仍存在；
5. 撤销其中一个；
6. 再次重新进入场次详情；
7. 确认只剩另一个。

不得 mock API。

测试数据继续全部使用虚构数据。
