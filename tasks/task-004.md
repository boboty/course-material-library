# Task 004 — 课后登记

## 本 Task 范围

### 1. 课后登记最终状态

使用 Task 3 已建立的 `usages` 数据模型，不新增第二套课后记录。

课后登记完成后，每条实际参与本次登记的使用记录应形成最终事实：

- 使用状态：
  - `已用`
  - `未用`
- 效果：
  - `未评`
  - `好`
  - `差`
- 现场反应：
  - 可选
  - 非空白字符串或 null

本 Task **原则上不需要新增 migration**。现有 `usages.status / effect / reaction` 已能承载本轮语义。

如果施工 Agent 认为必须新增字段或 migration，应停止施工并说明原因，不得自行增加 `used_at`、`reviewed_at`、`review_status` 等未来字段。

### 2. 计划素材默认按“已用”登记

产品定义要求：

**场次的计划素材默认视为“已用”。**

冻结实现语义：

- 进入课后登记页面时，数据库中仍为 `计划` 的素材，在 UI 上默认选择为 `已用`；
- **打开页面、刷新页面、读取 GET 接口不得自动修改数据库**；
- 只有用户明确执行“保存课后登记”后，才把最终状态持久化；
- 如果用户什么都不改直接保存，原计划素材应全部由 `计划` 变为 `已用`，效果保持 `未评`。

读操作不得产生“已经讲过”的业务事实。

### 3. 未用的语义

`未用` 表示：

**这条素材原本属于本场计划，但最终没有讲。**

为了保证数据可信，本 Task 冻结：

- `未用` 的效果必须为 `未评`；
- `未用` 的现场反应必须为 null；
- 如果用户把一条原本已填写“好 / 差 / 现场反应”的记录切换为 `未用`，保存时必须清除这些不再成立的数据；
- 不允许形成：
  - `未用 + 好`
  - `未用 + 差`
  - `未用 + 非空现场反应`

### 4. 已用素材的效果登记

对 `已用` 素材：

- 默认效果为 `未评`；
- 用户可以明确标记 `好` 或 `差`；
- 用户可以填写现场反应；
- 不设置“一般”；
- 不要求每条素材必须评价效果；
- 不根据现场反应内容自动推断好 / 差；
- 不自动修改素材本身的人工状态。

### 5. 补充现场临时使用的已有素材

课后登记页应允许搜索素材库，将“现场临时用了但备课时没有计划”的已有素材补入本场。

要求：

- 复用现有素材搜索能力；
- 加入后直接形成该场次的一条使用记录：
  - 状态 = `已用`
  - 效果 = `未评`
  - 现场反应 = null
- 同一场次、同一素材仍然最多一条使用记录；
- 如果该素材已经属于本场使用记录，不得重复新增；
- 草稿素材允许被补记为已用。

不得修改 Task 3 的计划接口语义：

`POST /api/v1/sessions/{session_id}/usages`

仍然只表示“加入备课计划”，只接收 `material_id`，并固定产生 `计划 / 未评`。

课后临时补记必须使用独立、明确的课后语义接口，不得让同一个 POST 根据隐藏参数或调用页面改变含义。

### 6. 现场临时新内容：只输入标题生成草稿

产品定义允许：

如果现场临时讲了一个库中不存在的内容，可以快速输入标题，直接生成草稿素材并记录本次使用。

本 Task 要求实现这一最小路径：

- 用户只输入标题；
- 标题必须非空白，长度继续遵守素材标题现有上限；
- 创建一条素材：
  - status = `草稿`
  - type = null
  - body = null
- 同一事务中创建该场次的使用记录：
  - status = `已用`
  - effect = `未评`
  - reaction = null
- 创建成功后立即出现在本场课后登记列表中；
- 后续素材补全留给素材编辑能力，不在本 Task 完成。

这里是课后快速补记的专用路径，不改变现有“日常快速录入”页面仍要求标题、类型、正文的语义。

### 7. 课后登记 API

提供明确的课后登记契约，至少支持：

- 读取场次当前使用记录；
- 一次保存本场使用记录的最终状态、效果与现场反应；
- 将已有素材作为现场临时使用补入本场；
- 只输入标题创建草稿素材并同时记录为本场已用。

推荐使用“场次级保存”而不是前端对每条 usage 连续发多个 PATCH：

例如：

- `PUT /api/v1/sessions/{session_id}/post-class`
- `POST /api/v1/sessions/{session_id}/post-class/usages`
- `POST /api/v1/sessions/{session_id}/post-class/materials`

具体路由命名可以按现有项目风格调整，但语义必须清楚。

场次级保存至少满足：

- 一次请求可提交本场多条使用记录；
- 每条 usage 必须真实属于该场次；
- 不接受其他场次的 usage id；
- 保存成功后，提交的 `计划` 记录必须变成 `已用` 或 `未用`，不能继续保持 `计划`；
- 非法状态、非法效果、空白现场反应继续由 Schema / 数据库约束保护；
- 保存过程应在一个数据库事务中完成，避免一场课只保存一半；
- 错误继续使用现有 error envelope，不暴露数据库细节。

V1 当前不做乐观并发控制，不为本 Task 新增版本号或锁机制。

## 冻结语义

### 打开课后登记页不是业务写操作

“计划素材默认视为已用”是**登记默认值**，不是“打开页面即自动确认已用”。

只有明确保存才能把 `计划` 改成最终事实。

### 保存后允许补登和修正

产品定义允许隔天补登。

因此本 Task 不做“提交后锁死”。

已经保存为 `已用 / 未用` 的记录，重新进入课后登记后仍允许人工修正：

- 已用 ↔ 未用；
- 未评 ↔ 好 / 差；
- 现场反应修改或清除。

所有修改都必须继续满足“未用不能带效果和现场反应”的数据规则。

### 历史效果不自动补齐

系统不得：

- 因为素材以前表现好而自动填“好”；
- 因为现场反应文字积极 / 消极而推断效果；
- 因为某素材经常使用而自动判断好坏。

### 不引入课后完成状态字段

本 Task 不新增“已登记 / 未登记”“reviewed”等状态字段。

当前 V1 的可信事实由每条使用记录本身承载。

## 当前不做

本 Task 不实现：

- 连续两次效果差提示；
- 自动建议复核；
- 同客户 / 同集团重复提醒；
- 素材家族；
- 素材与课程多对多关系；
- 素材人工状态自动变更；
- 素材完整编辑；
- 素材完整筛选；
- 批量 Markdown 导入；
- 课后登记完成率统计；
- 课后登记提醒 / 定时通知；
- 使用时长、讲述顺序、评分、学员人数等新字段；
- `used_at` / `reviewed_at` 等时间字段；
- 多用户协作、审批、权限；
- 新的缓存、消息队列或复杂基础设施。

不要为了后续“连续两次差”提前实现查询、提示或素材状态变更逻辑。

## 验收场景

至少覆盖以下行为：

1. 打开一个含计划素材的课后登记页，不保存直接退出，数据库仍保持 `计划`；
2. 两条计划素材不做修改直接保存后，都变为 `已用 + 未评`；
3. 将其中一条标记为 `未用` 后保存，得到 `未用 + 未评 + reaction=null`；
4. 一条已用素材可明确标记为 `好` 并保存现场反应；
5. 一条已用素材可明确标记为 `差`；
6. 将已有“好 / 差 / reaction”的记录改为 `未用` 后，效果和现场反应被清除；
7. 保存后刷新 / 重新进入，状态、效果、现场反应完整读回；
8. 已保存的课后登记允许再次修改并正确持久化；
9. 可以搜索一个未计划但已存在的素材，补记后形成 `已用 + 未评`；
10. 同一已有素材不能在同一场次重复补记；
11. 草稿素材可以作为现场临时使用的已有素材补记；
12. 只输入标题可创建一条 `type=null / body=null / status=草稿` 的素材，并同时形成 `已用 + 未评` 使用记录；
13. 标题为空白的现场临时新素材被拒绝，不产生素材，也不产生 usage；
14. 错误场次、错误 usage 归属、未知素材都有明确失败响应；
15. 一次场次级保存如果包含非法 usage，不能只保存部分记录；
16. Task 1 / Task 2 / Task 3 全部回归通过；
17. Task 3 的计划 POST 语义保持不变，仍不能由客户端写 status / effect / reaction；
18. 未实现连续两次效果差提示、自动素材状态修改等 Task 5+ 能力。

## E2E

至少新增一条真实完整流程，不得 mock API：

1. 创建三个虚构素材 A / B / C；
2. 创建虚构客户、课程、人群类型和场次；
3. 备课时计划 A、B；
4. 进入课后登记页；
5. 确认 A、B 默认显示“已用”，但此时仅进入页面不得让数据库自动变更；
6. 将 B 改为“未用”；
7. 将 A 标记为“好”，填写虚构现场反应；
8. 搜索并把未计划的 C 补记为现场已用；
9. 只输入标题快速新增虚构素材 D；
10. 保存课后登记；
11. 重新进入页面确认：
   - A = 已用 / 好 / reaction 保留；
   - B = 未用 / 未评 / reaction=null；
   - C = 已用 / 未评；
   - D 对应素材为草稿、type/body 为空，usage = 已用 / 未评；
12. 再修改 A 的效果或现场反应并保存，重新进入后确认修正成功。

另至少有一条移动端 viewport 验证：

- 375px 宽度；
- 核心登记控件、临时素材补记和保存动作可完成；
- 页面无影响核心操作的横向滚动。

测试数据继续全部使用虚构数据。
