# Task 10：素材列表增加状态筛选

## 目标

在素材列表增加“状态”筛选，使用户可以只查看指定状态的素材，并与现有关键词搜索共同使用。

本 Task 只实现状态筛选，不扩展为完整的素材筛选体系。

## 产品依据

`docs/product-v1.md` 已明确素材列表支持按状态筛选。

当前素材状态为：

- 草稿
- 可用
- 主力
- 待更新
- 退役

## 范围与边界

1. 素材列表增加状态筛选控件。

2. 支持：
   - 查看全部状态
   - 选择任一单个状态进行筛选

3. 状态筛选必须作用于真实后端查询结果，不得只在当前前端已加载数据中做本地过滤。

4. 状态筛选与现有关键词搜索可以同时使用：
   - 只输入关键词：按现有规则搜索
   - 只选择状态：按状态筛选
   - 同时设置关键词和状态：两项条件同时生效

5. 切换状态筛选后，列表应从第一页重新查询，避免保留旧分页位置造成空页或漏结果。

6. “全部状态”表示不附加状态条件。

7. 状态显示继续复用现有 Badge tone 规则，不新增颜色体系。

8. 后端如果已有状态过滤能力，应复用现有接口契约；
   如果没有，可为素材列表查询增加最小必要的 `status` 查询参数。

9. 状态参数非法时，应按项目现有 API 错误处理规则返回明确错误，不静默忽略非法状态。

## 明确不做

本 Task 不做：

- 类型筛选
- 课程筛选
- 人群筛选
- 行业筛选
- 标签筛选
- 多状态同时选择
- 素材编辑
- 素材家族
- 排序调整
- 新增 schema / migration
- 新增搜索引擎或缓存机制
- 改变素材状态定义

不要为了未来完整筛选体系提前设计复杂通用 Filter Framework。

## 验收

至少验证：

1. 默认进入素材列表时显示全部素材，现有行为不回退。

2. 选择“草稿”时，只返回草稿素材。

3. 选择“可用”“主力”“待更新”“退役”时，各自只返回对应状态素材。

4. 状态筛选与关键词搜索可以组合使用，结果同时满足两项条件。

5. 从某一筛选状态切回“全部状态”后，恢复不带状态限制的结果。

6. 切换筛选条件后分页回到第一页。

7. 非法状态参数不会被静默接受。

8. 前端状态筛选在桌面和 375px 宽度下均可正常使用，不产生明显溢出或关键操作不可达。

9. 不修改 schema / migration。

10. `make check` 通过。
