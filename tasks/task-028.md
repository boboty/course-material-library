# Task 28：V1 全链路验收与产品收口

## 目标
不新增业务能力，以真实使用路径对 V1 做一次完整产品级验收，确认“录入 → 备课 → 使用 → 复盘 → 积累”闭环成立，并修复验收中发现的 V1 阻断问题。

## 依赖
Task 20–27 全部 PASS。

## 产品依据
`docs/product-v1.md` 的全部 V1 范围与成功标准。

## 范围与边界
1. 从空库迁移到最新 head，并准备可走查数据。
2. 验证快速录入、编辑、批量导入。
3. 验证课程 / 人群 / 行业 / 标签 / 状态 / 类型等查找与筛选。
4. 验证素材家族。
5. 创建真实结构的客户、课程、场次并完成备课。
6. 验证课程优先与同客户 / 同集团重复提醒。
7. 完成课后登记：已用、未用、好、差、未评、临时加入已有素材、临时新建素材。
8. 验证复核过期与连续两次差提示。
9. 验证草稿待补全工作流。
10. 在 375px 下完整走一遍课后登记核心流程，确认可在约 5 分钟内完成正常一场课的登记操作；记录实际耗时和明显摩擦点。
11. 验证素材使用历史可信，系统提示不自动改变人工状态。
12. 验证 Demo 数据 seed / clean、迁移、Compose 交付与宿主机 make dev 基础链路。
13. 允许修复本轮验收发现的、明确属于 V1 阻断或回归的问题；不得借机扩展 V2 功能。
14. 对任何非阻断改进项记录为后续候选，不在本 Task 扩范围。

## 明确不做
- AI 推荐
- 向量数据库
- 多用户协作
- 复杂权限
- 附件
- 导出
- 母课 / 子课复杂体系
- 自动状态修改
- V2 功能扩张

## 验收
至少要求：
- `docs/product-v1.md` 中 V1 核心流程逐项有证据；
- make check / smoke / e2e / diff-check 全部通过；
- 空库 migration 与已有数据升级路径无回归；
- Docker Compose 从干净 volume 启动成功并自动迁移；
- 375px 核心流程可用；
- 记录已知限制，不把非阻断限制伪装成 PASS 失败；
- Independent Verifier 独立给出最终 V1 PASS 或 RC。

最终 PASS 后，更新 `PROGRESS.md` 为 V1 已验收基线。
